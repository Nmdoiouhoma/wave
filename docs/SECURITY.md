# Wave — security threat model v1 (phases 1-2)

Owner: qa-security · 2026-10-24 · Scope: auth, accounts, artists, tracks, uploads, streaming, infra (W-16); playlists, follows, likes, listens, user search (W-26, 2026-11-01).
Tests: `backend/tests/Security/` (php container; `MediaSecurityTest` in the worker image, `NginxEdgeTest` needs the stack; `ConcurrencySecurityTest` commits its own rows and forks real requests, ~10-20 PHP processes against the 512 MiB php container).

## Assets
| Asset | Why it matters |
|---|---|
| Credentials, refresh tokens, account tokens (verify/reset) | Account takeover |
| Private / processing / hidden tracks (audio + metadata) | Artists' unreleased work; existence must not leak (404, not 403) |
| JWT private key, `STREAM_SIGNING_KEY`, `APP_SECRET` (cursors), MinIO root/app keys | Forge sessions, stream URLs, read every object |
| Email addresses (`/me` only) | Enumeration, spam, phishing |
| Worker host (ffmpeg on untrusted files) | RCE / local file read / SSRF pivot |
| Activity journal (`activity_event`: IP /24-/48 prefix, HMAC IP hash, user agent), `ACTIVITY_IP_PEPPER` | Tracking users across accounts; pepper leak makes hashes brute-forceable (IPv4 space) |

## Actors
Anonymous internet client · registered **unverified** user · verified user · moderator · **admin** (ROLE_ADMIN only from the console, ADR 013) · thief holding a leaked token/URL · malicious uploader · compromised container on the `internal` network · supply chain (images, Composer, npm).

## Trust boundaries
1. Browser/mobile → nginx (only published port). 2. nginx → PHP-FPM (front controller only) and → MinIO (X-Accel `/_protected/`, `/media/`).
3. PHP → Postgres / MinIO (app credentials, 2 buckets). 4. Messenger → worker → ffmpeg/ffprobe on quarantined bytes. 5. Worker → SMTP.

## Threats, mitigations, status
| # | Threat | Mitigation in place | Status |
|---|---|---|---|
| T1 | Credential stuffing / brute force | Limits per IP+email, per IP, register per IP, constant-cost unknown-email login | OK when client IP is right; **open: XFF spoofable by peers in `TRUSTED_PROXIES` (F1)** |
| T2 | Account enumeration | Reset: identical 202, lookup in worker; login: same 401 body. Register 409 accepted (ADR 007) | OK (tested, timing within noise) |
| T3 | Account-token theft / guessing | 256-bit random, SHA-256 stored, single use (atomic UPDATE), purpose-bound, TTL 24 h / 1 h, newest voids older, 10/min/IP | OK (tested) |
| T4 | Refresh token theft | HttpOnly + SameSite=Strict + Path=/api/v1/auth cookie (web), rotation, revoke-all on password change/reset/suspension | **Partial: no reuse detection (F2); `Secure` depends on an env flag (F4)** |
| T5 | JWT forgery (`alg:none`, HS/RS confusion, expired, roles claim) | Lexik RS256 with fixed signer, `exp` required, header-only extractor, user + roles reloaded from DB | OK (tested) |
| T6 | Verified-email gate bypass | `security:` expression on all 6 gated phase-1 operations; no method override | OK (tested, incl. path/method variants) |
| T7 | IDOR / visibility leaks | Voters + lookups: invisible → 404 everywhere (read, mutate, stream-url, lists), visible-not-owner → 403; artistId ownership on upload/move. FB-18 (ADR 012): audiences `followers`/`close_friends` widen "visible" through one shared SQL predicate; an outsider (non-follower, follower outside close friends, ex-follower, removed close friend) gets the same 404 bytes as an unknown id on every track and post route, and `Track.visibility` is null/`public` for non-owners (audience not disclosed) | OK (tested, FB-18: TrackAudienceSecurityTest + TrackAudienceGapsTest) |
| T8 | Mass assignment | `JsonInputDecoder`: unknown property → 422, explicit DTOs, multipart whitelist | OK (tested) |
| T9 | Stream URL abuse | HMAC-SHA256 with dedicated key, `hash_equals`, canonical b64, exp 5 min, visibility/suspension/deletion re-checked on every Range request, `internal` location | OK (tested). A leaked URL is a 5-min bearer (accepted, ADR 001) |
| T10 | Direct object access | `/_protected/` internal, `/media/` query strings dropped, private bucket anonymous read limited to `audio/*` from the compose subnet | **Partial: any container on `internal` can read all private audio anonymously (F5)** |
| T11 | Hostile uploads (spoofed MIME, polyglot, bombs, traversal) | Size/MIME/extension pre-filter (415/413), random object keys (filename never used), quarantine bucket, ffprobe content sniffing, codec whitelist, 50 Mpx cap, WebP re-encode strips metadata | OK (tested) |
| T12 | ffmpeg as a pivot (HLS/concat/SDP, `file://`, URLs, argument injection) | `-protocol_whitelist file`, `-format_whitelist`, `file:` prefix, argv (no shell), timeouts, worker without published port, read-only FS, 1 GB / 512 MB tmpfs | OK (tested). Hardening ideas: `-codec_whitelist`, explicit `-enable_drefs 0` |
| T13 | PHP runtime (PHP2Shell, firewall CVE) | PHP 8.4.27 pinned by digest, Symfony 7.4.23, FPM `disable_functions`, upload_progress off, non-root, cap_drop ALL | OK; **`conflict` block of ADR 006 missing (F7)** |
| T14 | Secrets in git | Only dev placeholders in `backend/.env`; root `.env` and `*.pem` ignored; history clean | OK; **no prod guard against dev defaults (F6)** |
| T15 | XSS / open redirect / token leakage (front) | React only, no `dangerouslySetInnerHTML`; access JWT in memory; `safeNext` same-app paths; token pages strip `?token=` + `no-referrer` (meta and nginx) | OK. Prod CSP allows inline styles (low) |
| T17 | Social IDOR (playlists, likes, follows, listens) | `PlaylistVoter` + `PlaylistLookup`: invisible playlist → identical 404 on all 9 routes, other's public → 403 on mutations; others' private/processing/hidden tracks → 404 on add/like/listen; unlike removes one's own like whatever the visibility, without a like an invisible target → 404 byte-identical (body + headers) to an unknown one; non-owners never see items of invisible tracks | OK (tested, F14/F15 fixed). Accepted: `DELETE /users/{u}/follow` tells a suspended user (200) from an unknown one (404) FB-18: close-friends list readable/writable only via `/me/close-friends*` (no other user's list in any route); members = followers by composite FK to `follow` (no race, unfollow cascades); post playability is viewer-dependent, so the author's post on a restricted track is no longer playable by everyone (phase-3 wave-1 QA point 1 closed); accepted: `hashtag.post_count` and track counters include restricted content |
| T18 | Counter / position integrity under concurrency | `ON CONFLICT DO NOTHING` + bump, playlist `FOR UPDATE` (also taken by track deletion, F11), deferred unique position, advisory lock on listens, `FOR UPDATE` on app_user for the 200-playlist limit | OK for likes, follows, appends, listens, limit, deletion vs append to a playlist holding the track (tested, real processes). **Open: deletion vs append to a playlist NOT yet holding the track → item_count +1 drift, or 500 on FK (F17)** |
| T19 | Search enumeration / injection | Params bound, LIKE escaping in SQL after `wave_unaccent` (F10), q 2-100, cursor bound to q, offset < 200, 60/min + 1000/day, suspended excluded, no email in results | OK (tested) |
| T20 | `play_count` inflation | Count only against a fresh `listen_grant` from stream-url, consumed by every report (`DELETE … RETURNING`), `listenedMs ≤ elapsed + 2 s`, window `max(30 s, duration)`, 20/day per (user, track), DB clock only (ADR 010); 120 reports/min/user | OK (tested: grant loop stops at 20, concurrent reports count once, others' grants useless). Residual by design: 20/day per account and track; a 1 s track reaches it in 10 min |
| T21 | Hostile encodings (NUL, invalid UTF-8) | `RequestEncodingListener` (path once-decoded like the router, query keys and values → 400), `JsonInputDecoder` (NUL in values or keys at any depth → 422; invalid UTF-8 / lone surrogate is not JSON → 400), refresh token cookie/body → treated as absent; bearer parsed by Lexik (signed claims only) | OK (tested, F12 fixed; `%2500` stays the literal `%00`) |
| T22 | Post/comment existence oracles (FB-18 audiences) | `TrackAudience` (`visibleSql`/`postPlayableSql`) shared by `PostLookup`/`CommentLookup`, feeds, profile lists, reports (`ReportTargetResolver`), post creation; invisible → same 404 bytes as an unknown id; post-views silently ignored | OK (tested W-37: stranger, ex-follower, follower outside close friends, removed close friend × reports of 3 types, createPost, 7 post routes, comment delete, views — byte-identical incl. headers) |
| T23 | Report brigading / false mass reports | UNIQUE(reporter, type, id) over all rows (409 `already_reported`), auto-hide at the 5th distinct open reporter under advisory lock, moderator `dismiss` restores and closes; 20 reports/h | OK (tested: duplicate 409, 5 puppets hide post + comment, prior clip URL dies, dismiss restores `comment_count`, same puppets 409). Residual: 5 *new* accounts can re-hide after a dismiss (F21) |
| T24 | Notification leaks and spam loops | Upsert on `uniq_notification_unread`, retract on unlike/unfollow, read-time filters (suspended actors, target visible to recipient), actors as `UserSummary` (no email), `read` bound to `recipient_id` + `upTo` | OK (tested: 4 like/unlike + follow/unfollow loops → 0 then 1 item each, extra fields on `read` → 422, another user's `read` changes nothing) |
| T25 | Hostile text in captions, comments, hashtags | Multipart whitelist + `isCleanText` (NUL / invalid UTF-8 → 422), hashtag NFKC + `[\p{L}\p{N}_]{1,50}`, React text nodes only, API CSP `default-src 'none'` | OK except F19 (invalid UTF-8 field *name* → 500); zero-width/bidi never enter a hashtag (tested); combining-mark scripts truncated (F20, spec) |
| T16 | Supply chain | PHP digest-pinned; others tag-pinned; `make audit` | **MinIO = community fork `pgsty/minio`, tag-only (F8)** |
| T26 | Back-office privilege escalation (W-71) | `^/api/v1/admin` → ROLE_MODERATOR in `access_control`; admin-only ops `security: is_granted('ROLE_ADMIN')` with `read:false` + explicit `AdminQuery::requireAdmin()` in GET providers (403 before any lookup or body); `StaffGuard` (nobody acts on an admin, only an admin on a moderator); role body `Choice[ROLE_USER, ROLE_MODERATOR]`, strict whitelist; ROLE_ADMIN only from the console, last admin locked `FOR UPDATE` | OK (tested W-77: 18 routes × anonymous/user/moderator with unknown ids and junk bodies, no `admin.*` row; unsuspend of an admin 403 for all, mod→mod 403; 7 escalation bodies → 422, roles unchanged). Open: F26, F27 |
| T27 | Journal privacy (W-70) | Metadata key whitelist + token-shaped values, `note` on admin events only; IP kept as prefix + HMAC-SHA256(pepper) 16 bytes; XFF only from `TRUSTED_PROXIES` (empty in prod); user agent stripped of controls, 200 chars; purge 90 d / admin 365 d / acknowledged alerts 180 d | OK (tested W-77 with real requests: register/login fail/unknown email/login/report with spoofed XFF and hostile UA → no email, password, JWT, display name, report text or full IP stored; prefix and hash exact). Open: F29, F31, pepper absent from compose/infra |
| T28 | Alerts and announcements (W-72) | Alert upsert on `uniq_security_alert_open_subject` (dedup), acknowledgement row-locked, 409 when closed; announcements admin-only, strict bodies, RFC 3339 dates with calendar check, `endsAt > startsAt` on merged values, banner = 7 fields, JSON only, rendered as text by the client | OK (tested W-77: `<script>`/`onerror` stored verbatim and served as `application/json`, 15 invalid bodies → 422, scheduled/expired hidden, ack extra fields → 422). Open: F25, F28 |

## Findings (see W-16 report for file:line and fixes)
F1 X-Forwarded-For trusted from `172.16.0.0/12` (medium/high depending on deployment) · F2 refresh reuse not detected (medium, contract) · F3 rate-limiter rows never pruned (low) · F4 `REFRESH_COOKIE_SECURE` not tied to prod, no TLS/HSTS in the prod-shaped stack (medium) · F5 anonymous private-bucket read from every internal container (medium) · F6 dev-default secrets accepted at boot (low) · F7 ADR 006 Composer `conflict` missing (low) · F8 MinIO image provenance (medium) · F9 access JWT survives password reset ≤ 15 min (low, accepted).
Phase 2 (W-26, `docs/handoff/phase2-qa.md`): F10 fullwidth wildcards widen user search (medium) · F11 track deletion races playlist append, position gap then 500 on next append (medium) · F12 NUL bytes / invalid UTF-8 reach Postgres (medium) · F13 `play_count` inflatable by replaying listens (medium, contract) · F14 unlike/unfollow impossible on a now-invisible target (low) · F15 no rate limit on playlist creation / item add (low) · F16 suspended accounts listed in followers/following and reachable by profile/follow (low, decision).
Status after the W-26 fixes (`741829c`..`2be4d1c`, re-review `docs/handoff/w26-fix-qa.md`): F10-F16 closed (F13 per ADR 010, F16 per contract: `/users/{username}*` only). New: F17 track deletion racing an append to a playlist that does not hold the track yet: item_count drift or 500 FK violation (low) · F18 suspended accounts still shown as owner/artist on playlists, tracks and artists reachable by id or slug (low, phase 5 moderation).
Phase 3 (W-37, `docs/handoff/phase3-w37-qa.md`, tests `PhaseThreeReviewSecurityTest`): F19 multipart field name in invalid UTF-8 echoed in the 422 problem → `JsonResponse` throws inside the exception listener → 500 (low, open test) · F20 hashtags drop combining marks (`#हिन्दी` → `ह`), DATA_MODEL §9 pattern (low, spec) · F21 `dismiss` not sticky: 5 new accounts re-hide (low, decision) · F22 comment body of only zero-width chars accepted (low) · F23 `ModerationDecisionProcessor` `refresh()` after a concurrent delete → 500 (low) · F24 front shows « Signaler » on one's own comment until `me` loads, server 422 (low). Fixed since v3: stream tokens of a viewer suspended meanwhile → 404 (tested).
Back-office (W-77, `docs/handoff/w77-qa.md`, tests `BackOfficeSecurityTest`): F25 banner `:now` bound as `datetime_immutable` (seconds) against µs columns: a new banner hidden ≤ 1 s, an ended one shown ≤ 1 s (low) · F26 suspension `StaffGuard` checked outside the transaction, a concurrent console grant slips through (low) · F27 console grant accepts suspended/unverified accounts and the last-admin count includes suspended admins (low) · F28 announcement title/body accept bidi overrides and controls other than NUL (low) · F29 user agent kept as attacker text (`<script>` survives), admin UI must render it as text (low) · F30 moderators see user/content dashboard counters, ADR 013 says moderation counters only (info, decision) · F31 `activity_event` FKs `SET NULL`: future account deletion must delete non-admin events explicitly (open, phase 5).

## Out of scope v1 / next
